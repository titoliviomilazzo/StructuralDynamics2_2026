# 04 — Pull과 협업 (수업 저장소 사용법)

**목표:** 수업 저장소에서 자료를 받고, 브랜치를 만들어 작업하고, Pull Request로 제출한다.
**소요:** 25분
**선행:** [03 문서](03-first-commit-walkthrough.md)를 끝냈을 것

---

## 1. 수업 저장소 받아오기 (한 번만)

담당 교수에게 **Collaborator 초대 메일**을 받은 뒤 진행합니다.
(초대 수락 전에는 비공개 저장소라 clone이 안 됩니다.)

1. 메일 또는 `https://github.com/notifications` 에서 초대 **Accept**
2. VS Code에서 `Ctrl + Shift + P` → **Git: Clone**
3. 주소 입력
   ```
   https://github.com/titoliviomilazzo/StructuralDynamics2_2026
   ```
4. 저장 위치 지정 → **Open**

> 개인 실습 저장소(`dynamics-practice`)와 **다른 폴더**입니다. 둘 다 갖고 있으면 됩니다.

## 2. 최신 자료 받기 (Pull) — 매 수업 전

강의자료·예제가 업데이트됩니다. **작업을 시작하기 전에 항상 먼저** 받으세요.

1. VS Code에서 수업 저장소 폴더를 엽니다
2. Source Control 패널(`Ctrl+Shift+G`) → **⋯ → Pull**
   또는 왼쪽 아래 상태바의 **↻ 동기화 아이콘** 클릭
3. 새 파일이 생기거나 기존 파일이 갱신됩니다

> **Pull을 안 하고 작업하면** 나중에 충돌(conflict)이 납니다. 작업 시작 = Pull, 습관으로.

---

## 3. 브랜치 — 왜 필요한가

지금까지는 `main` 한 줄에서만 작업했습니다. 여러 명이 같은 `main`에 동시에 올리면
서로 덮어쓰기 사고가 납니다.

**브랜치 = 본선에서 갈라 나온 별도 작업 사본.**
검토용으로 도면철을 따로 한 부 떠서 거기에 표시하고, 검토가 끝나면 본철에 반영하는 것과 같습니다.

```
main    ──●──●──────────────●──   ← 항상 정상 동작하는 본선
              ╲            ╱
내 브랜치      ●──●──●────      ← 여기서 마음껏 작업, 끝나면 합침
```

내 브랜치에서 뭘 망가뜨려도 `main`은 멀쩡합니다. **그게 브랜치를 쓰는 이유입니다.**

## 4. 브랜치 만들고 작업하기

### ① 브랜치 생성
1. VS Code **왼쪽 아래 상태바**에 현재 브랜치 이름(`main`)이 보입니다 → 클릭
2. 위에 뜨는 목록에서 **Create new branch...**
3. 이름 입력 — 규칙: `hw1/학번-이름`
   ```
   hw1/32251234-홍길동
   ```
4. Enter → 상태바 이름이 바뀌면 성공

### ② 내 폴더에서만 작업
```
assignments/
└─ 32251234_홍길동/     ← 여기 안에서만 파일을 만들고 고칩니다
   ├─ hw1.py
   └─ README.md
```
> ⚠️ **다른 사람 폴더나 `docs/`, `examples/` 는 건드리지 마세요.**
> 각자 자기 폴더에서만 작업하면 충돌이 거의 발생하지 않습니다.

### ③ 커밋하고 브랜치를 서버에 올리기
1. `+` → 메시지 → **✓ Commit** (03 문서와 동일)
2. **Publish Branch** 버튼 클릭 (첫 push일 때 이 이름으로 나타납니다)

## 5. Pull Request(PR) 만들기 — 제출

PR = "제 브랜치의 작업을 본선(main)에 반영해 주세요"라는 **공식 제출 + 검토 요청**입니다.

1. 브라우저에서 수업 저장소 접속
2. 노란 띠에 **Compare & pull request** 버튼이 보임 → 클릭
   (안 보이면 상단 **Pull requests** 탭 → **New pull request** → 본인 브랜치 선택)
3. 작성
   - **Title**: `[HW1] 32251234 홍길동`
   - **Description**: 아래 양식을 채웁니다
     ```markdown
     ## 한 일
     - SDOF 자유진동 응답 계산 및 그래프 작성
     - 대수감쇠율로 감쇠비 역산, 입력값과 비교

     ## 결과
     - Tn = 0.9935 s, 역산 zeta = 0.050003 (입력 0.05, 상대오차 0.006%)

     ## 막혔던 곳 / 확인이 필요한 점
     - 초기속도가 0이 아닐 때 위상각 처리가 맞는지 확신이 없습니다.

     ## AI 사용 내역
     - Copilot Chat으로 Newmark-beta 구현 골격을 받고, 이론해와 비교해 검증했습니다.
     ```
4. **Create pull request**

### 검토 → 수정 → 반영
- 교수가 코드 줄에 코멘트를 답니다 → 알림이 옵니다
- 고칠 게 있으면 **같은 브랜치에서 수정 → commit → push** 하면 PR에 자동 반영됩니다
  (PR을 새로 만들 필요 없습니다)
- 통과하면 교수가 **Merge** → 본선에 합쳐집니다

### 다음 과제 시작 전
```
1. 상태바 브랜치 → main 선택
2. Pull  (방금 merge된 내 작업 + 다른 사람 작업 포함해 최신화)
3. 새 브랜치 생성 (hw2/32251234-홍길동)
```

## 6. 충돌(Conflict) — 났을 때만 읽으세요

같은 파일의 **같은 줄**을 두 사람이 다르게 고치면 Git이 판단을 포기하고 사람에게 묻습니다.

파일 안이 이렇게 됩니다.
```
<<<<<<< HEAD
zeta = 0.05
=======
zeta = 0.02
>>>>>>> main
```

**해결:**
1. VS Code가 충돌 부분 위에 **Accept Current Change / Accept Incoming / Accept Both** 버튼을 띄웁니다
2. 어느 쪽이 맞는지 **판단**해서 하나 고르거나, 직접 편집해서 옳은 내용만 남깁니다
3. `<<<<<<<`, `=======`, `>>>>>>>` 표시가 **하나도 안 남았는지** 확인
4. `+` → Commit

> **예방이 훨씬 쉽습니다.**
> ① 작업 전 항상 Pull ② 내 폴더 밖은 건드리지 않기 ③ 작업 단위를 짧게 끊어 자주 push

## 7. 팀 과제 협업 규칙 (권장)

| 규칙 | 이유 |
| --- | --- |
| 파일을 **기능 단위로 나눈다** (`model.py`, `plot.py`, `report.md`) | 같은 파일을 동시에 안 건드림 |
| 작업 시작 전 팀 채팅에 "나 `plot.py` 잡는다" 공지 | 물리적 충돌 방지 |
| 하루 끝에 무조건 push | 남이 내 최신본을 볼 수 있음 |
| `main`에 직접 push 금지, 항상 PR 경유 | 본선이 항상 동작 상태 유지 |
| PR은 작게, 자주 | 큰 PR은 검토도 충돌 해결도 지옥 |
